# Cart with a 15-minute Reservation, not instant atomic purchase

Issue #1 originally specced a single-Artwork "Buy now" flow: one Order per Artwork, purchase guarded by a DB transaction that atomically checked-and-flipped `sold`. Once we reviewed the actual Figma designs, we found a real multi-item cart (add several Artworks, one checkout) with explicit UX copy: *"Cada obra es única. Al estar en tu carrito, nadie más puede comprarla durante 15 minutos."* We chose to build the real thing rather than simplify the design away, since the reservation is central to how a one-of-a-kind-inventory storefront has to behave — without it, two customers could both add the same Artwork to their cart and only one can ever complete checkout, with no warning until payment.

This means an Artwork now has a transient **Reserved** condition (see `CONTEXT.md`), separate from and prior to **Sold**: adding to Cart creates a time-limited Reservation; it expires automatically and returns the Artwork to Available if checkout doesn't happen in time; only a completed Order flips Sold. An Order now covers one-or-many Artworks (via the Cart it was checked out from), not exactly one.

Consequence: the data layer needs an expiry mechanism (e.g. a `reserved_until` timestamp checked/cleaned up on read, or a scheduled job) rather than a single-statement transactional flag-flip. This is a materially bigger piece of work than the original spec assumed — revisit if reservation contention turns out to be rare enough in practice to simplify later.
